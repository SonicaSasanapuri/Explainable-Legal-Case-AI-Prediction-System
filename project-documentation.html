Architecture

The app is split into a FastAPI backend, React frontend, and model training pipeline. Runtime prediction depends on saved model artifacts.

React Frontend

Accepts case text, validates minimum length, sends requests to the backend, and renders verdict cards, SHAP keywords, and similar cases.

React 18 Axios CRA

FastAPI Backend

Coordinates prediction, retrieval, explanation, legal rule adjustment, consistency review, uncertainty handling, and argument simulation.

FastAPI Pydantic Uvicorn
->

ML and Search

Uses TF-IDF + XGBoost for classification, InLegalBERT embeddings for semantic retrieval, FAISS for search, and SHAP for explanation.

API Reference

The backend runs by default on `http://localhost:8000`. FastAPI docs are available at `/docs` when the server is running.

GET

/health

Checks whether the API is running and returns the backend version.

{
  "status": "ok",
  "version": "3.0"
}
POST

/predict

Predicts a case outcome from raw text. Requires at least 50 characters.

{
  "case_text": "Full case facts, arguments, or judgment text..."
}
POST

/predict-pdf

Accepts a text-based PDF upload using multipart form field `file` and returns the same prediction response shape.

curl -X POST http://localhost:8000/predict-pdf \
  -F "file=@case.pdf"
POST

/simulate

Analyzes legal arguments against the current verdict and estimates confidence or verdict shifts.

{
  "argument": "The arrest was illegal under Section 50 CrPC.",
  "current_verdict": "REJECTED",
  "current_confidence": 0.68,
  "similar_cases": [],
  "round_number": 1
}

Setup

Start the backend from the project root so the relative `models/` paths resolve correctly. Start the frontend from `frontend/`.

Backend

python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn backend.main:app --reload --port 8000

Frontend

cd frontend
npm install
npm start

Optional PDF Support

pip install pypdf

The PDF endpoint imports `pypdf` dynamically when a PDF is uploaded.

Useful URLs

Frontend: http://localhost:3000
Backend:  http://localhost:8000
API docs: http://localhost:8000/docs

Training Pipeline

`preprocess_and_train.py` cleans the dataset, trains the classifier, builds the FAISS index, and saves all runtime artifacts.

Load dataset

Reads `data/final_dataset.csv` with `text` and `label` columns.

Preprocess legal text

Extracts relevant legal sections, removes URL and citation artifacts, normalizes whitespace, and filters short samples.

Train classifier

Fits TF-IDF ngram features and trains an XGBoost binary classifier with class balancing.

Evaluate threshold

Compares default prediction with calibrated accept threshold `0.38`.

Build semantic index

Encodes cases with `law-ai/InLegalBERT`, normalizes embeddings, and stores them in FAISS.

Save artifacts

Writes `tfidf_vectorizer.pkl`, `xgboost_model.pkl`, `faiss_index.bin`, and `case_store.pkl` to `models/`.

Run training

python preprocess_and_train.py

Frontend Behavior

The React app is focused on text-based prediction and result visualization.

Input

Users paste case facts, arguments, judgment text, or petition details. The UI requires at least 50 characters.

Prediction

`App.jsx` posts to `http://localhost:8000/predict` and stores the returned result in React state.

Output

Verdict, confidence, generated explanation, SHAP keywords, and similar past cases are displayed in separate panels.

These screens show the prediction result, explainability panels, similar-case retrieval, and legal argument simulator in the working app.

Prediction Result

The result view presents the final verdict, confidence score, consistency status, uncertainty warning, and natural-language explanation.

Explainability and Retrieval

The SHAP panel highlights words that influenced the prediction, while the FAISS panel lists semantically similar accepted and rejected cases.

The simulator lets users challenge the prediction with legal arguments and observe how confidence or verdict direction may shift.

Important Files

A quick map of the codebase pieces you will edit most often.

Backend

  • `backend/main.py`: FastAPI routes and prediction pipeline.
  • `backend/predictor.py`: TF-IDF and XGBoost wrapper.
  • `backend/retriever.py`: FAISS and InLegalBERT retrieval.
  • `backend/explainer.py`: SHAP keyword extraction.
  • `backend/legal_rules.py`: legal rule adjustments.
  • `backend/simulator.py`: argument simulator.

Frontend and Training

  • `frontend/src/App.jsx`: main React workflow.
  • `frontend/src/components/`: UI components.
  • `preprocess_and_train.py`: training and FAISS build script.
  • `merge_datasets.py`: creates `data/final_dataset.csv`.
  • `models/`: runtime model artifacts.

Operational Notes

Things to know before presenting, testing, or deploying the project.

Legal safety

The system is decision-support software. It should not be treated as a substitute for professional legal advice.

Startup time

The backend may take time to start because it loads the XGBoost model, FAISS index, case store, SHAP explainer, and InLegalBERT model.

Production hardening

Restrict CORS, move hard-coded URLs to environment variables, remove secrets, add tests, and pin dependency versions.

Known limitations

PDF support requires text-based PDFs, the rule engine is keyword-based, and retrieval uses only the first 1,500 query characters.
